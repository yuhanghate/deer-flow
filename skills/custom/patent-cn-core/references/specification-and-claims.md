# 说明书与权利要求书（撰写与自查要点）

**对应指南**：请在现行《专利审查指南》**实质审查**部分中，检索**说明书**、**权利要求书**相关章节（名称以官方目录为准）。下文为**工作要点转述**，非条文引用。

---

## 说明书 — 一般原则（撰写时自检）

- **清楚**：主题明确，技术内容描述使本领域技术人员能够理解「要解决什么、如何实施」。避免仅靠商业宣传用语而无技术信息。
- **完整**：主题类型所需内容齐备（如装置/方法/用途各自应交代的关键要素）；**具体实施方式**应对权利要求提供支持。
- **可实现**：本领域技术人员根据说明书能够实施发明；**不得**只给设想或断言而无具体手段（除非该领域允许且与指南一致，由代理师判断）。
- **各节功能**：技术领域、背景技术、发明内容、附图说明、具体实施方式之间**逻辑连贯**；发明内容中的方案概述宜与权项**可对照**。
- **说明书摘要**：递交文本常含**单独摘要**（与正文一并输出时勿漏）。**字数、禁止标题、内容要素**等见 **`abstract-summary.md`**（与指南第一部分「说明书摘要」形式审查要点对齐）。

## 发明内容（说明书第三节）— 与交底书、权利要求的衔接（易错）

交底书常把材料拆成「技术方案 / 从属技术方案」等多节（如 4.2、4.3）便于撰写；**转入正式说明书时**，第三节「发明内容」应按**官式习惯**重组，避免把交底结构原样搬进说明书。

### 1. 与权利要求书的对应关系（覆盖权项信息）

- 发明内容应使本领域技术人员理解**权利要求所限定的技术方案**；**独立权利要求**中的必要特征应在发明内容中有**明确体现**（可与权项表述概括程度不同，但含义应对得上）。
- **从属权利要求**中的附加限定：宜在发明内容中通过 **「优选地，……」「进一步地，……」「在一种实施方式中，……」** 等**并入同一段方案叙述**，或明确指向后文具体实施方式中的对应记载，**避免**从属内容**仅**出现在实施例、而发明内容完全空白（是否全部展开由代理师根据篇幅与策略定夺，模型应提醒「核对权项—发明内容—实施方式」三角一致）。
- **自检**：起草或改写后，按权项 1、2、3… **逐项扫一遍**，每条中的技术特征是否在说明书（发明内容 ± 实施方式）中**找得到落脚点**。

### 2. 要解决的技术问题 — 用段落写

- 「要解决的技术问题」宜用**连续段落**叙述（一段或多段），**避免**交底书式的过多 **(1)(2)(3)** 短列表或细碎小标题把问题打成碎片（除非所内模板明确要求列表）。
- 多个并列问题时，可用**分段**：每段一个完整问题陈述，段间逻辑（主次、因果）清楚。

### 3. 技术方案与从属方案 — 说明书里不另立「从属技术方案」节

- **不要**在说明书「发明内容」中再设与交底 4.3 对等的标题（如单独一章「从属技术方案」或与权项序号对齐的小节）。
- **正确做法**：在「技术方案」同一叙事流中，先写**主方案**（对应独立项），再在同一节内用「优选地 / 进一步地 …」层层叠加**从属层次**，与权利要求的引用层次**语义一致**，版式上仍是**发明内容下的连贯正文**。

### 4. 有益效果（与方案、问题的衔接）

- 发明内容应写明**有益效果**：与「要解决的技术问题」及「技术方案」**逻辑对应**（解决了什么、如何体现），避免空泛宣传语；无实验数据时可用**定性**表述并标「待代理人核实数据支撑」。
- **版式**：效果部分**可用分段**（多段）书写——例如按「安全性 / 循环 / 成本」分述，或与权项层次对应的**效果递进**分段；**不要求**挤在技术方案同一段落末尾。所内若有固定小标题（如「本发明的有益效果在于：」下再分段），从其模板。

## 权利要求书 — 一般原则

- **版式与编号顺序**（易错）：正式稿须为 **1. 2. 3. …** 连续列表，**勿**用 `## 权利要求1（第一主题）` / `## 从属权利要求` 等标题打断；装置与方法多主题时的先后顺序与引用格式见 **`claims-layout-and-numbering.md`**。
- **清楚**：类型清楚（产品/方法等），技术特征表述确定；**引用关系**清楚（从属引独立或另一从属）。
- **简要**：无不必要冗余；同一构思不宜重复堆砌。
- **得到说明书支持**：权利要求中的每个技术特征在说明书（含实施例）中有**依据**；概括范围与实施例层次应匹配，**宽范围**需有代理师认可的概括基础。
- **必要技术特征**：独立权利要求从整体上反映技术方案，记载**解决技术问题的必要技术特征**（具体判断由代理师结合案情完成）。

## 说明书与权利要求的一致性

- 同一技术特征在**说明书、附图标记、权利要求**中**名称与含义一致**。  
- 功能性/效果性表述：须有说明书记载的**具体实现方式**支撑（领域与指南对「功能性限定」有特殊规定的，从代理师意见）。

## 具体实施方式 — 实施例 / 对比例标题（与国知局公开说明书通行体例对齐）

国家知识产权局**已公告**的发明/实用新型**说明书全文**（PDF 或网上公开 HTML 等官方载体）里，「具体实施方式」中的实施例标题，**常见**写法是：**单独一段只含标题行** `实施例1：`（**实施例** + **阿拉伯数字** + **中文全角冒号「：」**），**具体技术内容从下一个段落起写**（正式文本外侧的段落编号由排版系统生成，撰稿阶段不必照抄 `[0042]` 这类号）。不同年份、分册或排版系统可能略有差异，**以本所定稿模板或本案代理人指定的公告样本为准**；下列规则不绑定任何特定专利号或本地文件路径。

- **易错（Markdown 撰稿）**：**不要**在同一行标题后接长副标题；**不要**用 `### 实施例1：××××` 把「层级标题 + 说明」挤成一行（粘贴进 Word/WPS 常与正式稿不一致）。错误示例中的 `××××` 表示场景说明，应放到**下一自然段**。
- **交底书 / 撰稿 Markdown**：推荐 `实施例1：` 单独一行，空行后先用一两句话概括本例场景（承接原想写在标题里的副标题信息），再写「（1）（2）…」步骤。  
- **对比例**：同逻辑，`对比例1：` 单独一行，正文另起段。  
- **需要对照版式时**：由用户或代理师在对话/workspace 中提供**任意一份**已公告中文专利说明书（或本所范文）即可，模型用 `read_file` 看「具体实施方式」页——**无需**本 skill 附带或引用固定案号的 PDF。

## 附图与说明书

- 有附图时：附图说明与各图内容对应；说明书中描述结构宜能与**附图标记**对应。  
- 无附图：在附图说明中说明不适用或省略（按所内格式）。
