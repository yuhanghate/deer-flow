# 权利要求书 — 编号、顺序与版式（与国知局公开文本通行体例对齐）

**目的**：避免模型输出「按主题分节 + 打乱编号」的假权利要求书结构；与国知局**已公告**中文专利说明书中的**权利要求书**通行体例及常见双主题写法保持一致。**不依赖**特定案号 PDF：需要对照时由用户提供或指定任意已公告文本即可。

**效力**：以下为**行业常见体例与撰写习惯**，具体个案以代理师定稿及官方受理格式为准。

---

## 红线（最容易错）

1. **正文只能是「连续阿拉伯数字编号」的一条一条权利要求**，从 **1.** 起递增，**中间不得插入按主题拆块的 Markdown 标题**（错误示例：`## 权利要求1（第一主题：…）`、`## 权利要求2（第二主题：…）`、`## 从属权利要求`）。  
   - 若需向用户说明「第一主题 / 第二主题」，放在**对话说明**或**本节目标**里写，**不要**写进拟递交的「权利要求书」正文。
2. **顺序 = 编号顺序**：读者从上往下读，应能按 **1 → 2 → 3 → …** 理解引用关系；**不得**把从属权项整块挪到另一个独立项之前，导致编号与引用逻辑错位。
3. **一个编号只对应一条权利要求**；**不得**在正文里重复使用同一编号表示不同权项。

---

## 正确版式（与公告文本一致）

- 篇首可有单行标题：**权利要求书**（按所内模板）。  
- 其下**直接**列出：

```text
1. 一种……，其特征在于，……
2. 根据权利要求1所述的……，其特征在于，……
3. …
```

- **标准用语习惯**（与常见 PDF 一致）：  
  - 独立项：前序（主题名称） + **「其特征在于，」** + 区别特征。  
  - 从属项：**「根据权利要求N所述的……，其特征在于，」**（N 为阿拉伯数字；引多项时用 **「根据权利要求N至M任一项所述的……」** 或 **「权利要求N–M任一项」** 等所内固定表述，全文统一）。

---

## 顺序规则（单主题：装置/产品）

典型与**授权公告文本中「装置独立项 → 从属 → 方法独立项」**一类写法一致（具体案号因技术领域而异，不绑定单一文献）：

1. **独立权利要求**（如装置）排 **第 1 项**。  
2. **仅引用权项 1 的从属** 紧接其后（2、3、4…）。  
3. **引用另一从属项**的从属（如「根据权利要求4所述的…」）仍按 **编号递增** 排在后面，**不**因为「引的是从属」而另起一节标题。  
4. **另一类型的独立项**（如「一种……方法」）在**前述装置（及其实从属）写完后**，用**下一个连续编号**起写（例：权项 7 为方法独立项，可写「利用权利要求1–6任一项所述的……装置的方法」类表述）。

---

## 顺序规则（双主题：常见「方法 + 产品/电池」）

与 **「权利要求书_双主题版」类正确稿**一致的核心是：**编号仍连续，不按主题拆章**。

**允许且常见的顺序示例**：

1. **权项 1**：第一主题的**独立**权利要求（如制备方法），**其特征在于**，可含 **步骤S1、步骤S2** 等；步骤下再用 **(a)(b)(c)** 等分项（全文体例统一即可）。  
2. **权项 2**：第二主题的**独立**权利要求（如固态电池、装置），**其特征在于**，其中用 **「由权利要求1所述的……制得」** 等方式引用权项 1。  
3. **权项 3 及以后**：对权项 1 或权项 2 的**从属**，仍按 **3、4、5…** 递增，**不要**再插「## 从属权利要求」标题；若从属只限定方法，则写 **「根据权利要求1所述的……」**；若只限定产品，则写 **「根据权利要求2所述的……」**。

**错误**：先印一大段「从属权利要求」标题，再把权项 3 写在权项 2 之前；或把第二独立项仍标成「权利要求1」。

## 输出前自检清单（模型在交稿前心里过一遍）

- [ ] 是否从 **1.** 起**连续**编号到最后一项，无跳号、无重复号？  
- [ ] 是否**没有**用 `##` / 「第一主题」「第二主题」「从属权利要求」等**打断**编号列表？  
- [ ] 每一条从属的「根据权利要求N所述」中的 **N 是否 ≤ 本条编号** 且**被引权项确实存在**？  
- [ ] 方法引装置/产品时，**范围表述**（如 1–6 任一项）与**前面实际项数**是否一致？
