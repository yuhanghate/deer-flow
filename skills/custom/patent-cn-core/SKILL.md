# 中国专利撰写（核心）

## Overview

本 skill 帮助代理师把**技术交底书**整理成**符合中国专利法与《专利审查指南》的申请文件草稿**，并在撰写过程中发现**形式、支持、充分公开**方面的风险点。最终产出既要满足撰写规范，又要给代理人留出署名与定稿空间，模型不作出法律终局结论。

## Core Capabilities

- 交底书转专利申请文件（说明书六部分 + 权利要求书 + 摘要）
- 权利要求书撰写与梳理论证（独立项 + 从属项 + 编号顺序）
- 说明书各节撰写（摘要、背景、发明内容、附图说明、具体实施方式）
- 创造性/新颖性论证框架（三步法 + 区别特征链）
- 审查意见/OA 答复思路整理
- 对照《专利审查指南》的形式与实质自查
- 与 `pdf` skill 配合：从 PDF 抽取交底书全文
- 与 `doc-convert` skill 配合：最终交付 docx/PDF

## 工作流（按撰写顺序执行）

撰写完整专利申请文件时，严格按以下顺序推进。缺材料时先列《关键信息缺失清单》再动笔。

### 超长上下文承接

若上下文紧张或历史已被压缩，在继续撰写前先输出不超过 400 字的《对话承接稿》，须保留：交底核心方案与区别特征、已定术语与附图标记对照、权利要求现状、说明书各节完成度、已确认事实与「待代理人核实」汇总。

### Step 1：发明名称

从交底书中提炼发明名称，格式为「一种……的方法/装置/系统」，作为全文第一个 `#` 级标题。

### Step 2：摘要

**规则**（必须全部满足）：
- 连续一段，不设小标题行，内部不设任何子标题
- **含标点不超过 300 字**
- 内容须含：发明名称、所属技术领域、要解决的技术问题、技术方案要点、主要用途
- 不使用商业宣传用语
- **紧接在发明名称之后**（权利要求书紧接在摘要之后）
- 从独立权利要求与发明内容中提炼，不引入新特征

**自检**：字数 ≤300（含标点）？是否含名称/领域/问题/方案要点/用途五项？是否无商业宣传？

### Step 3：权利要求书

**数量**：以 **10～16 项** 为常规区间（按交底创新点层次伸缩，不为凑数而削足适履）。

**独立权利要求**：
- 默认 **1 项**，写清主发明点的全部必要技术特征，**核心创造点/区别特征必须进入独权**
- 交底中存在可并列保护且说明书能分别充分支持的不同完整技术方案时，可增设 **第二项独立权利要求**，且与首项在类型上并列互补（如产品/制造方法/使用装置等）
- **不得**为追求多类型独权而硬套不适配或缺乏支持的空壳独权

**从属权利要求**：非必要技术特征下沉到从属；每条从属须明确引用关系（"根据权利要求N所述的……"）。

**术语**：自定义术语首次出现须在说明书中有定义或明确指称。

**范围概括**：关键成分/步骤先写上位概念，再写优选范围与可选项。**禁止使用点值**：交底给出多个离散数值时（如 800℃、1000℃），必须合并为范围值（如 800~1000℃），不得以顿号/逗号/空格罗列；范围分隔符统一用 `~`。

**范围概括细则**：
- 多个离散点值 → 取**最小值**和**最大值**合并为范围，**保留与原始点值相同的有效数字位数**
- **分层写法**：独权写最宽范围 → 从权写优选子范围 → 实施例中保留原始点值作为具体实施条件。例如交底给了 120、135、150、165、180：独权写「120~180℃」，从权写「优选135~165℃」，实施例中仍写具体点值 120℃、150℃、180℃ 等
- **异常间隔识别**：若点值之间存在明显大跨度（如 1、50、200）或多个离散聚集区（如 1.2、1.3、1.4 和 5.0、5.1、5.2 两组），**不建议**合并为单范围，应标「待代理人核实：」，提示代理人考虑拆分为多个子范围或采用「选自以下范围/值之一」的并列写法
- **端值修饰**（如"约""大约"）由代理师决定策略，模型**不自行添加**此类修饰词

**版式与编号**（红线，最容易错）：
- 正式稿须为 **1. 2. 3. …** 连续阿拉伯数字编号，从 1 起递增，无跳号、无重复号
- **禁止**用 Markdown 二级标题按主题拆权项（错误示例：`## 权利要求1（第一主题）`、`## 从属权利要求`）
- 一个编号只对应一条权利要求
- 标准用语：独立项用「其特征在于，」；从属项用「根据权利要求N所述的……，其特征在于，」；引多项时用「根据权利要求N至M任一项所述的……」
- 另一类型的独立项在第一种类型及其从属写完后，用下一个连续编号起写

**自检**：是否从 1 起连续编号？是否无标题打断？独权是否包含核心区别特征？从属引用是否都指向已存在的权项？点值是否已合并为范围？

### Step 4：背景技术

**至少写 3 段**：
- **第1段**：相关技术领域背景信息 + 目前采用的现有技术方案
- **第2段**：现有技术存在的缺陷/不足/局限
- **第3段**：与本发明最相近的技术方案及其仍存的缺陷

**约束**：
- 所列举的缺陷必须能由本申请的技术方案对应解决
- **不得虚构**具体文献、实验数据、产品型号——无据处用概括性表述并标「待代理人核实：」
- 不编造对比文件号或专利号

**自检**：是否至少 3 段？是否列出现有技术及其缺陷？缺陷是否与本申请方案对应？是否无虚构文献？

### Step 5：发明内容

#### 4.1 技术问题
- 用**连续段落**书写，避免交底书式的 (1)(2)(3) 碎片列表
- 多个并列问题时可用分段，段间逻辑（主次、因果）清楚

#### 4.2 技术方案
- **一条流叙事**：先写主方案（对应独立项），再在同一节内用「优选地 / 进一步地 / 在一种实施方式中，……」层层叠加从属层次
- **禁止**在说明书「发明内容」中另立「从属技术方案」节或把交底书的分节标题原样搬入
- 从属限定要么并入同一段方案叙述，要么明确指向后文具体实施方式中的对应记载
- 发明内容记载须与**权利要求书逐项可对上**：每条权项的技术特征是否在发明内容或实施方式中找得到落脚点

#### 4.3 核心技术点的原理/作用/效果
- **每个核心技术特征/步骤叙述完毕后**，须紧跟一段写明该特征的：
  - **工作原理**：该特征如何运作
  - **在整体方案中的作用**：该特征与其他特征如何配合
  - **带来的技术效果**：该特征解决了什么问题、产生了什么结果
- 避免仅罗列特征而无论述

#### 4.4 有益效果
- **不少于 6 条**；若交底可归纳的可验证效果不足 6 条，则列出现有条目并单列「交底未载明、待补充以支撑之效果」类说明，**不得编造**效果或数据
- 每条尽量对应具体特征、结构、方法/工艺步骤、装置或性能指标之一
- 不写营销式口号，不出现具体的实验数值
- 可用一个或多个段落分段表述（不必挤在技术方案同一段落末尾），与「要解决的技术问题」及「技术方案」逻辑对应

**自检**：技术问题是否段落化？技术方案是否一条流且嵌入从属限定？每个核心技术点后是否写了原理/作用/效果？有益效果是否 ≥6 条且无具体数值？是否与全部权项可对上？

### Step 6：附图说明

- 有附图时：附图说明与各图内容对应；说明书中描述结构宜能与附图标记对应
- 无附图：在附图说明中写明「不适用」或「从略」（按所内格式）

### Step 7：具体实施方式

#### 7.1 实施例前的准备内容
在实施例1之前，须以**段落格式**补充以下两类内容：
- **原料/试剂/设备信息**：将交底书中分散的原料牌号、规格、供应商集中整理为连续段落
- **测试方法归纳**：统一归纳测试方法，明确引用**标准编号**；交底未给出标准号时写「标准号待补」或指向交底段落

#### 7.1.1 实施例参数对照表（必填）
当实施例≥3 且对比例≥2时，**须**在上述准备内容之后、实施例正文之前，增加一张**实施例与对比例参数对照表**：
- 表格**列**为各组实施例与对比例（例1、例2、例3、对比例1、对比例2…），**行**为关键工艺参数（如温度、压力、配比、时间等）
- 不同组之间参数不同的单元格用**加粗**标注，方便审查员快速识别差异
- 表格内容须与后文实施例的文字描述**完全一致**，不得出现矛盾数据
- 实施例<3 或对比例<2 时可省略此表

#### 7.2 实施例与对比例
- 至少 **3 个实施例 + 2 个对比例**，围绕权利要求的技术点安排对比逻辑
- 对比例与实施例在交底允许范围内保持除关键区别特征外的条件一致
- 交底已载明的原料牌号、工艺参数、测试条件、标准编号等**照录**
- 交底未给出的数值、对比结果、标准编号等一律用 **「XX」「待补」** 等占位，**禁止编造**实验或检测数据

#### 7.3 实施例/对比例标题格式
- 标题单独一行：`实施例1：` / `对比例1：`（实施例 + 阿拉伯数字 + 中文全角冒号「：」）
- 具体技术内容**另起段落**写，不要在同一行接副标题

#### 7.4 对比总结段落
- 所有实施例和对比例写完后，须在具体实施方式中增加一个**对比分析段落**
- 将实施例与对比例的实验数据/结果逐项对照，明确对应到前文所述的**有益效果**
- 证明各技术点的有效性
- 缺少的数据用「XX」占位，**禁止编造**

**自检**：实施例前是否集中了原料信息和测试方法？实施例 ≥3 + 对比例 ≥2？参数对照表：当实施例≥3 且对比例≥2 时是否已生成？是否无编造数据？标题格式是否正确？是否有对比总结段落？

## 交付件尾部固定章节（必填）

以下三个章节**必须**出现在默认输出末尾（即代理人工作附件模式），不可省略、不可合并。若用户明确要求仅输出递交用文本（A 类），则省略此三章。

### 进一步改进建议

```
## 进一步改进建议

1. [补充实施例/对比例]：交底书实施例或对比例数量不足时，指出需要补充的实验条件、参数组合与对比逻辑
2. [完善数据与参数范围]：简述需补充的实验数据、测试结果或参数范围（如温度/配比/阈值的端值与优选范围）
3. [细化技术细节]：简述交底书未载明但撰写所需的具体信息（如原料牌号、设备型号、标准号、电路实现等）
```

- 至少列出 **3 条** 改进建议；交底信息充分时可适当减少，但**不得少于 1 条**
- 每条须指出**当前缺失/不足的内容**及**建议补充的方向**
- 不得编造具体数据，仅给出建议方向

### 待审核

根据交底书内容，列出以下需要审核的技术问题：

```
## 待审核

1. **[数据矛盾]**：指出交底书中数值不一致、前后矛盾之处
2. **[机理疑问]**：对交底书中机理解释的合理性提出质疑
3. **[范围概括建议]**：对权利要求中范围值概括是否合理给出建议（过宽/过窄）
```

- 至少列出 **3 条**，交底信息完整时可适当减少，但**不得少于 1 条**
- 每条须指出具体问题及其对专利申请的影响
- 不得编造矛盾或疑问

### 待申请人确认事项

```
## 待申请人确认事项

1. [确认项一]：需要确认的具体内容（如具体参数、原料牌号、测试设备等）
2. [确认项二]：需要确认的具体内容
3. [确认项三]：需要确认的具体内容
```

- 至少列出 **3 项**，交底信息完整时可适当减少，但**不得少于 1 项**
- 每项须指出**待确认的具体内容**及**对专利申请的影响**
- 包括但不限于：实验数据补充、参数范围确认、测试方法/设备型号、现有技术文献检索

## 交付格式

- **默认交付 `docx`**：用户请求"下载文稿/导出专利"且未指定格式时，默认产出 `docx`
- **`md` 仅作为中间产物**：允许先在沙箱内生成 `md` 供组稿或审阅，但最终交付优先转为 `docx`
- **每次生成或修改专利草稿后，必须调用转换工具将最新 `md` 转为 `docx` 并交付**，不得仅输出 `md` 文本或沿用旧版 `docx`
- **用户坚持要 PDF 时**：先交付 `docx`，并明确建议用户在本机 Word/WPS 中"另存为 PDF"
- **仅在用户明确要求"直接生成 PDF"时**，再走 `doc-convert`，使用 `--force-direct-pdf`，并提示中文兼容性风险
- 若转换工具不可用，须明确告知用户"无法生成 docx"并说明原因

## Markdown 格式要求（确保 Word 标题样式）

所有章节标题**必须**使用 Markdown `#` 语法，确保 `pandoc` 转换后保留层级样式：

| 层级 | Markdown 写法 | Word 效果 |
|------|--------------|----------|
| 一级标题 | `# 1. 技术领域` | 标题 1 |
| 二级标题 | `## 3.1 技术方案` | 标题 2 |
| 三级标题 | `### 实施例 1：` | 标题 3 |

**关键规则**：
- `#` 后必须跟一个空格，如 `# 标题` 而非 `#标题`
- 禁止纯文本标题（不带 `#` 的行会被当作普通段落）
- 摘要用 `# 摘要` 作为一级标题，正文直接开始写
- 权利要求书用 `# 权利要求书` 或 `# 2. 权利要求书`，正文保持连续编号

## 交付分层

- **（A）递交用文本**：说明书六部分 + 权利要求书 + 说明书摘要，体例符合常规申请文件，**不夹带**「进一步改进建议」「待审核」等非递交章节
- **（B）代理人工作附件**（对话中单独成章或另存为工作稿）：含「进一步改进建议」「待审核」「待申请人确认事项」与《合规自检清单》，**不替代**代理人法律判断与定稿

## 强约束

1. `resources/samples/` 中的内置样板仅用于内部校准，**不得对用户展示**路径或案号
2. 即使用户要求"引用对比文件"，也只能引用**用户自己提供**或**运行时外部检索得到**的文献
3. 对外默认用泛化措辞（"现有技术""公开方案"），不暴露内部样板编号与路径
4. 输出前必须自检：若出现 `CN` 号或内部样板路径，先删除/改写再交付
5. **禁止**：编造实验数据、对比文件内容、审查员原话或官方文书
6. **禁止**：替代代理师签字与递交决策

## 行为准则

1. **先想后写**：交底信息不足时先列《关键信息缺失清单》，不自行脑补技术方案、对比文件或实验数据
2. **简洁为上**：权利要求只写必要技术特征；背景不虚构文献；不为凑数添加非必要从属项；不编造交底书未提供的测试方法或实施例
3. **手术刀式修改**：修改已有专利稿时只改用户指定的部分，不顺手调整不相关的标题格式、段落顺序、术语表达；发现无关问题只提醒不删除
4. **目标驱动**：输出后逐项过质量检查清单，每一条均通过才算完成交付；交底书给 5 条效果就只写 5 条并标注"待补充"，不为凑 6 条而编造

## 内容标注约定

- (a) 来自用户的事实：直接写入
- (b) 模型的推断/假设：前缀「待代理人核实：」
- (c) 指南或法条：只写原则性提醒，**不编造**具体款号

## 创造性/新颖性论述

- 只整理「区别特征—技术问题—效果」链条与论据草稿
- **不写**「必然授权/必然驳回」等结论性表述
- 是否显而易见以审查员/复审结论为准

## 输出前质量检查清单

请在交付前逐项检查：

- [ ] 摘要：≤300字（含标点）、一段到底、无小标题、含名称/领域/问题/方案要点/用途
- [ ] 摘要位置：紧接在发明名称之后，权利要求书紧接在摘要之后
- [ ] 权利要求书：10-16 项，连续编号（1.2.3.…），无标题打断
- [ ] 独立权利要求：包含核心创造点/区别特征，非必要特征已下沉从属
- [ ] 独立权利要求数量：至少 1 项，如有多项则类型并列互补
- [ ] 从属引用：每条从属引用的权项编号均存在且 ≤ 当前编号
- [ ] 术语：自定义术语首次出现时有定义
- [ ] 范围：权利要求中无点值罗列，离散值已合并为范围（用 `~`）
- [ ] 背景技术：至少 3 段，列出现有技术、缺陷、最相近技术
- [ ] 背景技术：所举缺陷能由本申请方案对应解决，无虚构文献
- [ ] 发明内容-技术问题：用段落书写，非碎片列表
- [ ] 发明内容-技术方案：一条流，从属用「优选地」嵌入，无另立「从属技术方案」节
- [ ] 发明内容-核心技术点：每个核心特征后写了原理/作用/效果
- [ ] 发明内容-有益效果：≥6 条，无具体数值，分段表述，与方案/问题对应
- [ ] 发明内容：与权利要求逐项可对上
- [ ] 具体实施方式-实施例前：集中了原料牌号段落和测试方法归纳
- [ ] 具体实施方式-参数对照表：当实施例≥3 且对比例≥2 时已生成，列=各组实验、行=关键参数，数据与正文一致
- [ ] 具体实施方式-实施例：≥3 个实施例 + ≥2 个对比例
- [ ] 具体实施方式-标题：实施例N：/对比例N：独占一行，正文另起段
- [ ] 具体实施方式-对比总结：有对比分析段落，证明有益效果
- [ ] 具体实施方式-数据：缺数据用 XX 占位，无编造
- [ ] 进一步改进建议：≥1 条，不编造数据
- [ ] 待审核：≥1 条，不编造矛盾
- [ ] 待申请人确认事项：≥1 项
- [ ] Markdown 标题：所有标题使用 `#` 语法
- [ ] docx 已交付：最新专利草稿已通过转换工具转为 `docx` 文件并交付
- [ ] 强约束：无内部样板路径、无虚构 CN 号、无编造数据
