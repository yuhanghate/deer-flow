# 中国专利撰写（核心）

## Overview

本 skill 帮助代理师把**技术交底书**整理成**符合中国专利法与《专利审查指南》的申请文件草稿**，并在撰写过程中发现**形式、支持、充分公开**方面的风险点。最终产出既要满足撰写规范，又要给代理人留出署名与定稿空间，模型不作出法律终局结论。

## Core Capabilities

- 交底书转专利申请文件（说明书六部分 + 权利要求书 + 摘要）
- 权利要求书撰写与梳理论证（独立项 + 从属项 + 编号顺序）
- 说明书各节撰写（摘要、背景、发明内容、附图说明、具体实施方式）
- 创造性/新颖性论证框架（三步法 + 区别特征链）
- 审查意见/OA 答复思路整理
- 对照《专利审查指南》的形式与实质自查
- 与 `pdf` skill 配合：从 PDF 抽取交底书全文
- 与 `doc-convert` skill 配合：最终交付 docx/PDF

## 工作流（按撰写顺序执行）

撰写完整专利申请文件时，严格按以下顺序推进。缺材料时先列《关键信息缺失清单》再动笔。

### 超长上下文承接

若上下文紧张或历史已被压缩，在继续撰写前先输出不超过 400 字的《对话承接稿》，须保留：交底核心方案与区别特征、已定术语与附图标记对照、权利要求现状、说明书各节完成度、已确认事实与「待代理人核实」汇总。

### Step 1：发明名称

从交底书中提炼发明名称，格式为「一种……的方法/装置/系统」，作为全文第一个 `#` 级标题。

### Step 2：摘要

**规则**（必须全部满足）：
- 连续一段，不设小标题行，内部不设任何子标题
- **含标点不超过 300 字**
- 内容须含：发明名称、所属技术领域、要解决的技术问题、技术方案要点、主要用途
- 不使用商业宣传用语
- **紧接在发明名称之后**（权利要求书紧接在摘要之后）
- 从独立权利要求与发明内容中提炼，不引入新特征

**自检**：字数 ≤300（含标点）？是否含名称/领域/问题/方案要点/用途五项？是否无商业宣传？

### Step 3：权利要求书

**数量**：以 **10～16 项** 为常规区间（按交底创新点层次伸缩，不为凑数而削足适履）。

**独立权利要求**：
- **至少 2 项**，且类型必须成对出现（方法⇄产品），**不因交底书只写了一种类型就只保留一种**：
  - 交底给**制备方法** → 自动补出对应**产品**独权，写法为「一种……产品，其特征在于，由权利要求1～N任一项所述的方法制得」（product-by-process 写法）
  - 交底给**产品结构** → 自动补出对应**制备方法**独权
  - 方法与产品都有 → 视情况增设**应用/用途**独权（如"……磁体在新能源汽车电机中的应用"）
- 第一独权写清主发明点的全部必要技术特征，**核心创造点/区别特征必须进入独权**
- 第二独权用引用型写法（"由……方法制得"/"采用……结构"），不另列与首独权重复的技术特征
- 交底中存在可并列保护且说明书能分别充分支持的不同完整技术方案时，可增设**第三项独立权利要求**，且与首项在类型上并列互补
- **不得**为追求多类型独权而硬套不适配或缺乏支持的空壳独权

**多路径工艺方案的独权架构**：交底书给出两种并列工艺路径（如湿法碳化 OR 加压碳化、A法 OR B法）时：
- 独立权利要求中用"和/或"或"……或……"同时覆盖两条路径，不得只写其中一种
- 每条路径的具体工艺参数**必须下沉到各自的从属链**，两条从属链互不交叉，分别引用独权
- 示例：独权写"进行碳化预处理，得到碳化再生细骨料" → 从权A写"所述碳化预处理为湿法碳化，具体步骤为……" → 从权B写"所述碳化预处理为加压碳化，具体步骤为……"

**从属权利要求**：非必要技术特征下沉到从属；每条从属须明确引用关系（"根据权利要求N所述的……"）。

**术语**：自定义术语首次出现须在说明书中有定义或明确指称。

**范围概括**：关键成分/步骤先写上位概念，再写优选范围与可选项。**禁止使用点值**：交底给出多个离散数值时（如 800℃、1000℃），必须合并为范围值（如 800~1000℃），不得以顿号/逗号/空格罗列；范围分隔符统一用 `~`。

**范围概括细则**：
- 多个离散点值 → 取**最小值**和**最大值**合并为范围，**保留与原始点值相同的有效数字位数**
- **分层写法**：独权写最宽范围 → 从权写优选子范围 → 实施例中保留原始点值作为具体实施条件。例如交底给了 120、135、150、165、180：独权写「120~180℃」，从权写「优选135~165℃」，实施例中仍写具体点值 120℃、150℃、180℃ 等
- **异常间隔识别**：若点值之间存在明显大跨度（如 1、50、200）或多个离散聚集区（如 1.2、1.3、1.4 和 5.0、5.1、5.2 两组），**不建议**合并为单范围，应标「待代理人核实：」，提示代理人考虑拆分为多个子范围或采用「选自以下范围/值之一」的并列写法
- **端值修饰**（如"约""大约"）由代理师决定策略，模型**不自行添加**此类修饰词

**交底参数类型→权利要求范围映射表**（收到交底书后按此表逐参数判断写法）：

| 交底书参数模式 | 独权写法 | 从权写法 | 实施例写法 |
|-----------|---------|---------|-----------|
| **多个离散点值**（如 800℃、1000℃） | 最宽范围 800~1000℃ | 优选子范围（如有聚集区） | 保留各原始点值 |
| **已给范围**（如 20~40℃） | 直接采用 | 进一步优选子范围（如有） | 端值或中间点值 |
| **单个点值**（如 25℃） | 「XX范围待补」+ 标「待代理人核实：」 | — | 保留该点值 |
| **"作为优选"→"进一步优选"层级** | 上位范围 | 第一优选范围 → 第二优选范围 | 具体值 |

> 交底只给单个点值时**禁止自行编造范围**，用占位语交由代理人决定策略。

**版式与编号**（红线，最容易错）：
- 正式稿须为 **1. 2. 3. …** 连续阿拉伯数字编号，从 1 起递增，无跳号、无重复号
- **禁止**用 Markdown 二级标题按主题拆权项（错误示例：`## 权利要求1（第一主题）`、`## 从属权利要求`）
- 一个编号只对应一条权利要求
- 标准用语：独立项用「其特征在于，」；从属项用「根据权利要求N所述的……，其特征在于，」；引多项时用「根据权利要求N至M任一项所述的……」
- 另一类型的独立项在第一种类型及其从属写完后，用下一个连续编号起写

**自检**：是否从 1 起连续编号？是否无标题打断？是否至少 2 项独权且类型成对（方法+产品或产品+方法）？第二独权是否用引用型写法？独权是否包含核心区别特征？从属引用是否都指向已存在的权项？点值是否已合并为范围？方法从属与产品从属是否各自成链？

### Step 4：背景技术

**至少写 3 段**：
- **第1段**：相关技术领域背景信息 + 目前采用的现有技术方案
- **第2段**：现有技术存在的缺陷/不足/局限
- **第3段**：与本发明最相近的技术方案及其仍存的缺陷

**约束**：
- 所列举的缺陷必须能由本申请的技术方案对应解决
- **不得虚构**具体文献、实验数据、产品型号——无据处用概括性表述并标「待代理人核实：」
- 不编造对比文件号或专利号

**自检**：是否至少 3 段？是否列出现有技术及其缺陷？缺陷是否与本申请方案对应？是否无虚构文献？

### Step 5：发明内容

#### 5.1 技术问题
- 用**连续段落**书写，避免交底书式的 (1)(2)(3) 碎片列表
- 多个并列问题时可用分段，段间逻辑（主次、因果）清楚

#### 5.2 技术方案

**整体结构**：按权利要求书的**全部权项顺序**逐条列举（独权+从权都要覆盖），采用**一条流叙事**——先写主方案（对应独立项的全部技术特征），再用「优选地」「进一步地」层层叠加从属限定，与权利要求的引用层次语义一致。每条独权一个 `###` 级子标题。

```
### 独权1技术方案（第一独立权利要求的技术方案，对应权1）
[独权1的全部技术特征，用一段完整描述]

优选地，[从权2的技术限定]。[该限定带来的技术效果]

优选地，[从权3的技术限定]。[该限定带来的技术效果]
……

### 独权2技术方案（第二独立权利要求的技术方案，对应权N）
[独权2的全部技术特征，如"由权利要求1～N任一项所述方法制得的产品"]

优选地，[独权2下的第一条从权限定]。[该限定带来的技术效果]
……

### 核心技术点的原理/机理/作用
[将5.3节的原理/机理/作用写在此处，见下方5.3节要求]
```

**规则**：
- **顺序一致**：说明书中技术方案的描述顺序与权利要求书编号顺序完全相同（权1→独权1、权2→权2下的从权、权N→权N），不得打乱
- **进一步补充**：在权利要求基础上补充技术细节、原理说明、优选实施方式，不照搬权利要求原文
- **每条独权一个 `###` 级子标题**，标题中须写明该独权的类型（方法/产品/系统）
- **独权下的从属限定用「优选地」「进一步地」嵌入**，每个从权限定单独成段，**不使用** "1.1 / 1.2" 编号，**不用** "在步骤S1中进一步限定" 这类嵌套表述——直接用「优选地」开头，段内自行写明该限定所属的步骤/部位
- 从权段内写法：**优选地，[技术限定]。[该限定带来的技术效果]**，段内可先用半句交代所属部位（如"在步骤S1中，优选地……"），再写限定和效果
- 独权与从权的引用关系须在从权段中体现（如"优选地，步骤S1中的碳化处理条件进一步限定为……"）
- **发明内容记载须与权利要求书逐项可对上**：每条权项的技术特征是否在发明内容中找得到落脚点
- **禁止**在技术方案各独权/从权段落中混入 5.3 节的原理/机理/作用内容——原理统一放在"核心技术点的原理/机理/作用"节

**示例**（以方法独权为例）：

```markdown
### 基于再生骨料碳化的混凝土收缩补偿改性方法

本发明提供的一种基于再生骨料碳化的混凝土收缩补偿改性方法，包括以下步骤：

步骤S1、再生微粉的制备与改性：将废弃硬化水泥浆体破碎、细磨得到再生微粉，将所述再生微粉分为两部分，一部分进行碳化处理得到碳化再生微粉，另一部分进行热活化处理得到热活化再生微粉；

步骤S2、再生细骨料的碳化预处理：将再生细骨料进行碳化预处理，得到预处理再生细骨料；

步骤S3、混凝土配制：将所述碳化再生微粉和热活化再生微粉按一定取代率替代水泥，将所述预处理再生细骨料按一定取代率替代未处理的再生细骨料，与水混合搅拌后浇筑成型，养护得到收缩补偿改性混凝土。

优选地，步骤S1的碳化处理条件进一步限定为：温度20~30℃、湿度40~60%、二氧化碳浓度≥95%，碳化时间不少于24h。该条件范围的设定使再生微粉中的氢氧化钙充分转化为方解石，水化硅酸钙脱钙生成碳酸钙与二氧化硅凝胶，有效填充微粉颗粒内部孔隙，提升微粉的填充效应与火山灰活性。

优选地，步骤S2的碳化预处理进一步限定为湿法碳化处理：将再生细骨料与质量分数3~8%的碳酸钠溶液按固液比1:15~1:25混合，加入0.3~0.8wt%的催化剂，室温下反应5~10h。湿法碳化中碳酸钠提供碱性环境，催化剂加速碳化反应，再生细骨料表面生成致密碳酸钙层，降低骨料吸水率并优化界面过渡区。
```

#### 5.3 核心技术点的原理/机理/作用

本节对应技术方案中 `### 核心技术点的原理/机理/作用` 子标题。**每个核心技术特征/步骤叙述完毕后**，须紧跟一段写明该特征的：

- **工作原理**：该特征如何运作
- **在整体方案中的作用**：该特征与其他特征如何配合
- **带来的技术效果**：该特征解决了什么问题、产生了什么结果

**注意**：本节内容不混入 5.2 节各独权/从权的描述中，统一放在「核心技术点的原理/机理/作用」节。

#### 5.4 有益效果

**条数**：按独立技术贡献点计数，**不拆分同一件事凑数**。建议 **6～8 条**，交底可归纳几条就写几条，但**不得少于 4 条**。

**每条必须写成完整因果链（五段式）**：

> [具体技术手段] → [微观/化学/物理层面的作用机理] → [由此避免的现有技术缺陷（可选但鼓励写）] → [中间层次的工艺/结构改善] → [最终宏观性能提升]

**禁止跳过中间机理层**：不能只写"通过X技术，提高了Y性能"。必须交代X如何在材料/结构/反应层面起作用。例如：

- ❌ 错误写法：`通过添加稀土氢化物，提高了磁体矫顽力。`
- ✅ 正确写法：`稀土氢化物粉末在烧结中发生氢原子与稀土氧化物还原反应，提升表层稀土浓度、降低富稀土杂质熔点，有效补充液相烧结剂，避免真空烧结中因稀土挥发与氧氮吸附形成高熔点化合物而导致晶粒合并生长，从而拓宽致密化与晶粒正常生长的工艺窗口，为后续晶界扩散提供通畅路径，最终协同提升矫顽力。`

**对照现有技术**：每条应说明如果不采用本技术手段会导致什么问题或现有技术的什么缺陷被避免，不只写"做到了什么"。

**协同效果整体写**：多步骤/多特征组合产生的效果须作为一条整体写，**禁止**把各子步骤的效果割裂罗列成多条。最后落在"各步骤/各特征的协同作用实现了……"。

**可验证结构/性能**：效果须落到可验证的具体结构特征或性能指标上（如"距表面500~1000μm深度形成连续均匀富重稀土壳层"），**不出现**具体实验数据/数值（如"矫顽力提高了10.36 kOe"）。

**红线：交底书数值不得进入有益效果**。交底给了具体数值（如"干缩补偿率21.3%~30.1%""强度浮动-0.5%~+14.1%"）时，有益效果中**必须**改写为趋势性描述（如"显著降低干缩率""有效保持或提升抗压强度"），具体数值**只保留在**实施例正文、参数对照表、对比总结中。不得以"交底书给的就不能改"为由将数值写进有益效果。

**交底数值→有益效果转换示例**：
- ❌ 错误写法：`湿法碳化再生细骨料在25%~100%取代率下对干缩的补偿为21.3%~30.1%。`
- ✅ 正确写法：`湿法碳化再生细骨料在较宽取代率范围内均能显著降低再生砂浆干缩率，补偿效果优于未碳化处理的再生细骨料。`

**与问题/方案对应**：每条有益效果须与「要解决的技术问题」及「技术方案」中的具体特征形成一一对应关系，**不写**交底书中无对应技术支撑的空洞效果。

**自检**：技术问题是否段落化？技术方案顺序是否与权利要求编号顺序完全一致？每条独权是否有独立子标题？独权下的从属限定是否用「优选地」「进一步地」嵌入（非"1.1 / 1.2"编号）？从权限定是否能追溯到对应独权？是否在权利要求基础上作了补充而非照搬？原理/机理/作用是否统一放在"核心技术点的原理/机理/作用"节？每个核心技术点后是否写了原理/作用/效果？有益效果是否按独立贡献点计数（6～8条）、每条是否写了完整因果链（手段→机理→缺陷避免→结构改善→性能提升）、是否避免了割裂拆分同一协同效果、是否无具体实验数值、是否与全部权项和技术问题可对上？

### Step 6：附图说明

- 有附图时：附图说明与各图内容对应；说明书中描述结构宜能与附图标记对应
- 无附图：在附图说明中写明「不适用」或「从略」（按所内格式）

### Step 7：具体实施方式

#### 7.1 实施例前的准备内容（红线，不得跳过）
实施例前**必须**先写出以下两类段落，交底未给出时用占位符补全，**不得因交底缺失而跳过**：
- **原料/试剂/设备信息**：将交底书中分散的原料牌号、规格、供应商集中整理为连续段落；交底未给出时写「原料：XX，牌号/规格待补，供应商待补」
- **测试方法归纳**：统一归纳测试方法，明确引用**标准编号**；交底未给出标准号时写「标准号待补」或指向交底段落
- **实施例参数对照表**：当实施例≥3 且对比例≥2时，须在上述两项之后增加参数对照表（详见 7.1.1）

**【关键：实施例配方数据来源】** 撰写实施例和对比例正文时，必须从交底书的**参数对照表**或**实施例文字**中提取各组分具体用量（份数），禁止用"? 份"或"XX 份"替代交底书中已有的具体数值。仅交底书确实未给出的组分用量才用占位符。

#### 7.1.1 实施例参数对照表（必填）
当实施例≥3 且对比例≥2时，**须**在原料信息和测试方法归纳之后、实施例正文之前，增加一张**实施例与对比例参数对照表**：
- 表格**列**为各组实施例与对比例（例1、例2、例3、对比例1、对比例2…），**行**为关键工艺参数（如温度、压力、配比、时间等）
- 不同组之间参数不同的单元格用**加粗**标注，方便审查员快速识别差异
- 表格内容须与后文实施例的文字描述**完全一致**，不得出现矛盾数据
- 实施例<3 或对比例<2 时可省略此表

#### 7.2 实施例与对比例
- 至少 **3 个实施例 + 2 个对比例**，围绕权利要求的技术点安排对比逻辑
- 对比例与实施例在交底允许范围内保持除关键区别特征外的条件一致

**【关键规则：交底书已有配方数据时必须照录】**
- 交底书中参数对照表、实施例正文已载明的**原料牌号、工艺参数、各组分具体用量（份数/重量/体积）、测试条件、标准编号等，必须逐一照录到生成的实施例文字中**，不得用"?"或"XX"占位代替已有数据
- 如果交底书以**参数对照表**形式给出实施例各组分的用量，撰写各实施例正文时**必须从表中提取对应数值填入**，禁止出现"? 份原料X"之类的不完整配方
- 交底书**确实未给出**的数值（如某实施例缺少的某个组分用量）才用 **「XX」「待补」** 等占位，并在「待申请人确认事项」中列出
- **禁止编造**交底书中没有的实验或检测数据

#### 7.3 实施例/对比例标题格式
- 标题单独一行：`实施例1：` / `对比例1：`（实施例 + 阿拉伯数字 + 中文全角冒号「：」）
- 具体技术内容**另起段落**写，不要在同一行接副标题

#### 7.4 对比例设计原则与对比总结写法（核心，交底书常见问题集中于此）

交底书通常只给少量实施例和零散对比例，**照抄交底书会导致对比例与发明点脱节、对比逻辑断裂、分析无层次**。须按以下原则重新组织：

**A. 对比例设计五原则**

- **一一对应**：每个核心发明点须有至少一个对比例来验证，对比例总数 ≥ 核心发明点数量
- **控制变量**：每个对比例只改变一个变量，其余条件与对应实施例完全相同，用语"其余工艺完全相同"
- **数据链完整**：尽量避免对比例数据全为"/"的情况——即使基体性能差，也应给出可测量的参数（密度、剩磁等），只有确实无法进行后续步骤时才用"/"，并说明原因
- **不照抄交底书**：交底书实施例须重写为专利体例（步骤化描述 + 参数完整 + 条件明确），不能原文照搬；交底未给出的参数用"XX"/"待补"占位
- **边界验证**：除核心发明点的排他性对比外，建议增设 1 项范围边界验证对比例（如最佳范围 vs 范围外），证明参数选择的非显而易见性

**B. 对比总结写法**

- 所有实施例和对比例的对比分析集中于**一个对比总结节**（`## 对比分析` 或 `## 对比总结`），不分散在各对比例后，不使用编号列表（1. 2. 3.）将分析拆成互不关联的要点
- 可用多个自然段落分别论述不同组别的对比，但每段内部须含三层：**①数据对比**（实施例 vs 对比例的数值差）→ **②机理解释**（从微观结构层面解释差异原因，如"晶粒异常长大→晶界缺失→扩散通道不足→Dy堆积于表面"）→ **③映射有益效果**（对应到发明内容中第N条有益效果）
- 总对比总结节须逐一覆盖全部实施例和对比例，不漏项

**C. 对比总结写法示例**（自然段落，不用编号列表）：

> 实施例1~3的28天抗压强度较OPC浆体浮动-0.5%~+14.1%，28天干缩率较未碳化处理的再生砂浆降低21.3%~30.1%，而对比例1（不使用CRCP和TRCP且不碳化再生细骨料）及对比例3（仅使用CRCP和TRCP但不碳化再生细骨料）的干缩率均显著高于实施例1~3。从微观结构层面，湿法碳化在液相中促使碳酸钠与再生细骨料表面的Ca(OH)₂反应生成致密CaCO₃层，该碳化层填充骨料表面孔隙并优化了骨料-浆体界面过渡区（ITZ），减少了ITZ处的微裂纹扩展通道，从而显著降低了砂浆的干燥收缩。这一数据对比与机理解释对应了发明内容有益效果第1条所述的"湿法碳化再生细骨料有效降低混凝土干缩率"。
>
> 对比例5（仅使用CRCP不使用TRCP）及对比例6（仅使用TRCP不使用CRCP）的抗压强度和干缩性能均劣于同时使用两者的实施例3和实施例6。机理上，CRCP在浆体中提供碳酸钙成核位点和微填充效应，降低孔隙率；TRCP中的活性SiO₂和Al₂O₃在水泥水化碱性环境下发生火山灰反应，生成C-S-H凝胶补充浆体相强度。二者缺一时，要么缺乏成核位点导致水化产物分布不均，要么缺乏活性组分导致浆体相密实度不足，均无法达到协同优化的结构状态。该对比验证了发明内容有益效果第2条所述的"CRCP与TRCP协同提升混凝土综合性能"。

**自检（Step 7 核心项，仅关注交底书易错处；常规格式/数量检查在末尾清单中统一过一遍）**：
- 交底书参数对照表/实施例已有数据是否**全部照录到实施例文字中**（无"? 份""XX"等对已有数据的占位）？
- 对比例是否覆盖全部核心发明点？是否每个只改变一个变量？
- 对比总结是否集中于一个节（可分多段落但不分散、不编号列表）、是否逐一覆盖全部实施例和对比例？
- 实施例是否重写为专利体例而非照抄交底书？

## 交付格式

- **默认交付 `docx`**：用户请求"下载文稿/导出专利"且未指定格式时，默认产出 `docx`
- **`md` 仅作为中间产物**：允许先在沙箱内生成 `md` 供组稿或审阅，但最终交付优先转为 `docx`

- **写入草稿文件**：生成完整专利草稿后，**先**将全文写入 `workspace/patent-draft.md`，**再**从该文件调用转换工具转为 `docx` 交付，作为本 thread 内改模式的唯一数据源
- **用户坚持要 PDF 时**：先交付 `docx`，并明确建议用户在本机 Word/WPS 中"另存为 PDF"

- 若转换工具不可用，须明确告知用户"无法生成 docx"并说明原因

- **（B）代理人工作附件**（对话中单独成章或另存为工作稿）：含「进一步改进建议」「待审核」「待申请人确认事项」与《合规自检清单》，**不替代**代理人法律判断与定稿

## 行为准则

1. **先想后写**：交底信息不足时先列《关键信息缺失清单》，不自行脑补技术方案、对比文件或实验数据
2. **简洁为上**：权利要求只写必要技术特征；背景不虚构文献；不为凑数添加非必要从属项；不编造交底书未提供的测试方法或实施例
3. **手术刀式修改**：修改已有专利稿时只改用户指定的部分，不顺手调整不相关的标题格式、段落顺序、术语表达；发现无关问题只提醒不删除。若用户要求修改已有专利稿且非从零生成，建议改用 `patent-cn-edit` skill
4. **目标驱动**：输出后逐项过质量检查清单，每一条均通过才算完成交付；有益效果按独立技术贡献点计数（6～8条），每条须写完整因果链，不为凑数拆分或编造（同 5.4 规则）

### 写模式 vs 改模式触发判定

收到用户输入后先判断：

```
已有 patent-draft.md 且用户针对该草稿提出修改意见？
  → 是：局部修改（温度、参数、实施例、权项个别特征、对比总结）→ 使用 patent-cn-edit，只输出修改段落

  → 否（全新交底书或用户明确要求"从零撰写"）→ 使用 patent-cn-core 全文生成
```

**常见触发场景**：
- "把温度改成1000℃" → edit 模式
- "增加对比例，单独使用CRCP和TRCP" → edit 模式
- "参考下述内容重新撰写专利" + 给出全新独权架构 → 可视为结构重写，全文生成
- "交底书如下：……" → write 模式

- (a) 来自用户的事实：直接写入
- (b) 模型的推断/假设：前缀「待代理人核实：」
- (c) 指南或法条：只写原则性提醒，**不编造**具体款号

## 创造性/新颖性论述

- 只整理「区别特征—技术问题—效果」链条与论据草稿
- **不写**「必然授权/必然驳回」等结论性表述
- 是否显而易见以审查员/复审结论为准

## 输出前质量检查清单

请在交付前逐项检查：

- [ ] 摘要：≤300字（含标点）、一段到底、无小标题、含名称/领域/问题/方案要点/用途
- [ ] 摘要位置：紧接在发明名称之后，权利要求书紧接在摘要之后
- [ ] 权利要求书：10-16 项，连续编号（1. 2. 3. …），无标题打断
- [ ] 独立权利要求：包含核心创造点/区别特征，非必要特征已下沉从属
- [ ] 独立权利要求数量：至少 2 项，类型成对（方法+产品或产品+方法），第二独权用引用型写法，如有多项则类型并列互补
- [ ] 从属引用：每条从属引用的权项编号均存在且 ≤ 当前编号
- [ ] 术语：自定义术语首次出现时有定义
- [ ] 范围：权利要求中无点值罗列，离散值已合并为范围（用 `~`）
- [ ] 背景技术：至少 3 段，列出现有技术、缺陷、最相近技术
- [ ] 背景技术：所举缺陷能由本申请方案对应解决，无虚构文献
- [ ] 发明内容-技术问题：用段落书写，非碎片列表
- [ ] 发明内容-技术方案：顺序与权利要求编号顺序完全一致，每条独权有独立子标题，独权下的从属限定用「优选地」「进一步地」嵌入（非"1.1 / 1.2"编号），在权利要求基础上进一步补充细节而非照搬
- [ ] 发明内容-技术方案：原理/机理/作用统一放在"核心技术点的原理/机理/作用"节，未混入各独权/从权描述中
- [ ] 发明内容-核心技术点："核心技术点的原理/机理/作用"节中每个核心特征写了原理/作用/效果
- [ ] 发明内容-有益效果：按独立贡献点计数（6～8条），每条写了完整因果链（手段→机理→缺陷避免→结构改善→性能提升），协同效果整体写不拆分，无具体实验数值（交底数值已改写为趋势性描述），与方案/问题对应
- [ ] 发明内容：与权利要求逐项可对上
- [ ] 具体实施方式-实施例前：集中了原料牌号段落和测试方法归纳
- [ ] 具体实施方式-参数对照表：当实施例≥3 且对比例≥2 时已生成，列=各组实验、行=关键参数，数据与正文一致
- [ ] 具体实施方式-实施例：≥3 个实施例 + ≥2 个对比例
- [ ] 具体实施方式-标题：实施例N：/对比例N：独占一行，正文另起段
- [ ] 具体实施方式-对比总结：集中于一个节（可分多段落但不分散、不编号列表），逐一覆盖全部实施例和对比例
- [ ] 具体实施方式-对比总结写法：每条含数据对比→机理解释→映射有益效果，不漏项
- [ ] 具体实施方式-对比例设计：每个发明点有对应对比例，每个对比例只改变一个变量
- [ ] 具体实施方式-对比例数据：无数据全为"/"的对比例（除非确实无法进行后续步骤且已说明原因）
- [ ] 具体实施方式-实施例体例：重写为专利体例，未照抄交底书原文
- [ ] 具体实施方式-数据：交底书已有数据全部照录，实施例文字中无"? 份""XX"等对已有数据的占位；仅交底书确实缺失处用 XX 占位，无编造
- [ ] 进一步改进建议：≥1 条，不编造数据（仅 B 类工作附件）
- [ ] 待审核：≥1 条，不编造矛盾（仅 B 类工作附件）
- [ ] 待申请人确认事项：≥1 项（仅 B 类工作附件）
