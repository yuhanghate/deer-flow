# 中国专利修改（改模式）

## Overview

本 skill 用于**已有专利稿件的局部修改**。用户指定要改的部分后，只输出修改后的段落文字，不重新生成全文。最终用户可直接复制粘贴到 Word 文件中。

## Core Capabilities

- 实施例/对比例的参数修改与扩写
- 权利要求个别特征的修改
- 参数对照表联动更新
- 对比总结段落同步调整
- 发明内容技术方案对应段落修改
- 多实施例/对比例参数联动修改

## 工作流（收到修改指令后严格按序执行）

禁止跳过任何步骤直接输出修改内容，禁止全文重写。

### 超长上下文承接

若对话历史已被压缩，读取 `workspace/patent-draft.md` 获取最新稿件状态继续修改。不依赖早期对话历史回忆修改内容。

### Step 1：意图识别与作用域判定

收到用户修改指令后，先判断三件事：

1. **用户明确说了改哪里？**（"改实施例1"→ 明确）
2. **用户没明确说但能推断？**（"温度改成1000℃"→ 搜索温度出现在哪个实施例/对比例）
3. **改了这个会影响哪些连带内容？** 参见下方「联动更新检查清单」

### Step 2：修改范围确认

向用户输出修改范围，格式如下：

```
本次修改范围：
- 直接修改：[章节路径，如 具体实施方式 > 实施例1]
- 联动更新：[需要同步更新的章节，如 参数对照表 > 实施例1列；如无则写"无"]
```

### Step 3：读入当前稿件

读取 `workspace/patent-draft.md`，获取最新完整状态。该文件由写模式生成，是本 thread 内唯一的专利草稿。若文件不存在，告知用户"未找到专利草稿，请先用写模式生成草稿"。

### Step 4：逐段输出修改内容并更新文件

**只输出被修改的段落**，使用以下固定输出格式：

```
## 修改：[章节路径]

[直接输出修改后的完整段落，用户可直接复制粘贴到 Word]

---

## 修改：[章节路径]（如有多处修改）

[直接输出修改后的完整段落]

---

## 说明（可选）

- [简短说明改了什么、为什么改，如果原因显而易见可省略]
- [提示需要同步手动更新的位置（如有）]
```

**规则**：
- 不输出未修改的章节
- 不展示 diff 格式（红绿行、SEARCH/REPLACE 块等）
- 每个修改段落标明归属章节路径，让用户知道粘到 Word 的哪个位置
- 用户可直接复制每段内容粘贴到 Word 文件对应位置
- **输出完毕后，将修改后的段落写回 `workspace/patent-draft.md`**：先读取完整文件内容，将对应段落替换为修改后的版本，再将完整文件写回，保持文件始终为最新状态

### Step 5：下一步建议

每轮修改输出完毕后，根据本次修改的内容，主动给出下一步建议供用户选择：

```
## 本次修改已完成

已修改：[简述本次修改内容]
已同步更新：[联动章节，如无则写"无"]
草稿文件已更新：workspace/patent-draft.md

接下来可以：
1. 继续修改其他内容（请描述要改什么）
2. 检查本次修改的联动项是否遗漏
3. 生成当前版本的参数对照表
4. 补充对比总结段落
5. 结束修改，导出最新版 docx
```

**规则**：
- 建议列表须根据本次修改内容**动态裁剪**，只给出合理的选项（如未涉及实施例则不出现选项3、4）
- 用户回复数字即可执行对应操作，回复其他内容则作为自定义修改指令进入下一轮
- 选项1 始终保留，保证用户可随时自由输入
- 选项5（导出 docx）仅在用户之前提过交付格式或修改轮次≥2 时出现

## 各章节修改规则

修改前先定位到对应章节，按以下核心约束进行修改。修改内容须遵守 `patent-cn-core` 中对应章节的撰写规则。

### 摘要

- 连续一段，不设小标题行
- **含标点不超过 300 字**
- 内容须含：发明名称、所属技术领域、要解决的技术问题、技术方案要点、主要用途

### 权利要求书

- **连续阿拉伯数字编号**：1. 2. 3. … 从 1 起递增，无跳号、无重复号
- **禁止**用 Markdown 二级标题按主题拆权项
- **独立权利要求至少 2 项，类型成对**（方法⇄产品）：交底给方法须补产品独权（"由……方法制得"），交底给产品须补方法独权
- 独立项用「其特征在于，」；从属项用「根据权利要求N所述的……，其特征在于，」
- 交底给出两种并列工艺路径时，独权用"和/或"或"……或……"同时覆盖，各路径参数下沉到各自的从属链，两条从属链互不交叉
- 引多项时用「根据权利要求N至M任一项所述的……」
- **禁止使用点值**：离散数值合并为范围值（用 `~`）；交底只给单个点值时用「XX范围待补」+ 标「待代理人核实：」，禁止自行编造范围；范围概括规则参见 `patent-cn-core` 的「交底参数类型→权利要求范围映射表」
- 从属权利要求须明确引用关系，引用编号必须存在
- 方法从属与产品从属各自成链

### 背景技术

- 至少 3 段：领域背景 + 现有技术缺陷 + 最相近技术及其仍存缺陷
- **不得虚构**具体文献、实验数据、产品型号

### 发明内容

- **技术问题**：用连续段落书写，避免 (1)(2)(3) 碎片列表
- **技术方案**：一条流叙事，从属用「优选地 / 进一步地 / 在一种实施方式中」嵌入
- **禁止**另立「从属技术方案」节
- 每个核心技术特征后须写原理/作用/效果
- **有益效果**：按独立技术贡献点计数（4～8条），每条须写完整因果链（手段→机理→缺陷避免→结构改善→性能提升），不写具体实验数值（交底给的具体数值须改写为趋势性描述，数值只保留在实施例/对比总结中），协同效果整体写不拆分
- 发明内容须与权利要求书逐项可对上

### 具体实施方式

- 实施例前须有**原料/试剂/设备信息**段落和**测试方法归纳**段落
- 实施例≥3 且对比例≥2 时须有**参数对照表**
- 至少 3 个实施例 + 2 个对比例（如为新增）
- 标题格式：`实施例1：` / `对比例1：`（独占一行，正文另起段）
- 交底未给出数值用「XX」「待补」占位，**禁止编造**
- 所有实施例和对比例后须有**对比总结段落**

### 对比例设计原则（改模式同样适用）

- **一一对应**：每个核心发明点须有至少一个对比例来验证
- **控制变量**：每个对比例只改变一个变量，其余条件"完全相同"
- **数据链完整**：避免对比例数据全为"/"，尽量给出可测量参数
- **不照抄交底书**：须重写为专利体例（步骤化 + 参数完整 + 条件明确）
- **对比总结集中于一个节**：可分多段落分别论述，集中于一个对比总结节，不使用编号列表拆分；每条分析含三层：①数据对比 → ②机理解释（微观结构层面） → ③映射有益效果
- 全部对比例分析逐一覆盖，不漏项

## Markdown 格式要求（通用）

| 层级 | Markdown 写法 | Word 效果 |
|------|--------------|----------|
| 一级标题 | `# 1. 技术领域` | 标题 1 |
| 二级标题 | `## 3.1 技术方案` | 标题 2 |
| 三级标题 | `### 实施例 1：` | 标题 3 |

**关键规则**：
- `#` 后必须跟一个空格，如 `# 标题` 而非 `#标题`
- 禁止纯文本标题（不带 `#` 的行会被当作普通段落）

## 联动更新检查清单

修改完成后，自动检查以下联动关系。修改了某个章节时，检查表中列出的其他章节是否需要同步更新。

| 修改了 | 需要同步检查 |
|--------|------------|
| **发明名称** | 摘要中的名称引用 |
| **摘要** | 与独立权利要求、发明内容是否一致 |
| **独立权利要求新增/删除特征** | 从属权利要求引用链、发明内容技术方案、摘要方案要点 |
| **独立权利要求新增第二独权（产品/方法）** | 发明内容中须补充对应产品/方法技术方案描述、具体实施方式支持段落 |
| **独立权利要求修改技术特征** | 发明内容主方案对应段落、摘要 |
| **独权新增/修改并列工艺路径** | 各路径从属链是否独立、是否分别引用独权 |
| **从属权利要求修改** | 发明内容中「优选地/进一步地」对应段落 |
| **从属权利要求新增/删除** | 发明内容对应层级 |
| **权利要求范围修改（端值/范围）** | 发明内容对应参数描述、实施例对应参数 |
| **背景技术** | 发明内容中「要解决的技术问题」是否对应 |
| **发明内容-技术问题** | 背景技术中的缺陷描述、有益效果是否对应 |
| **发明内容-技术方案** | 权利要求书对应特征、具体实施方式对应段落 |
| **发明内容-核心技术点原理/作用/效果** | 有益效果列表 |
| **发明内容-有益效果增减** | 核心技术点后的效果段落、对比总结段落 |
| **有益效果中是否出现具体实验数值** | 交底数值须改写为趋势性描述，数值移至实施例/对比总结 |
| **附图说明** | 具体实施方式中的附图引用标记 |
| **具体实施方式-原料/试剂/设备信息** | 各实施例中的原料牌号、规格 |
| **具体实施方式-测试方法** | 各实施例中的测试条件、标准号 |
| **具体实施方式-参数对照表** | 各实施例/对比例正文中的对应数据（必须一致） |
| **实施例参数（温度、时间、配比等）** | 参数对照表对应行、对比总结段落 |
| **实施例数量增减** | 参数对照表整列、有益效果条数、实施例编号连续性 |
| **对比例参数** | 参数对照表对应列、对比总结段落 |
| **对比例数量增减** | 参数对照表整列、实施例与对比例对比逻辑 |
| **对比实验结果** | 对比总结段落、有益效果 |
| **具体实施方式-对比总结段落** | 有益效果列表、各实施例/对比例数据 |

## 强约束

1. **禁止**编造实验数据、对比文件内容、审查员原话或官方文书
2. **禁止**替代代理师签字与递交决策
3. **禁止**全文重写，只输出修改段落
4. 若出现 `CN` 号或内部样板路径，先删除/改写再交付

## 行为准则

1. **只改用户指定的部分**，不顺手调整不相关的标题格式、段落顺序、术语表达
2. **发现无关问题只提醒不删除**
3. **修改后写回文件**：见工作流 Step 4

## 内容标注约定

- (a) 来自用户的事实：直接写入
- (b) 模型的推断/假设：前缀「待代理人核实：」
- (c) 指南或法条：只写原则性提醒，**不编造**具体款号

## 创造性/新颖性论述

- 只整理「区别特征—技术问题—效果」链条与论据草稿
- **不写**「必然授权/必然驳回」等结论性表述

## 与 patent-cn-core 的分工

`patent-cn-core` 管**从零生成**专利稿（交底转专利、写全文）；本 skill 管**已有稿件的局部修改**。修改内容须遵守 `patent-cn-core` 中对应章节的撰写规则（范围概括、编号、格式等）。

## 与 patent-domain-* 的分工

`patent-domain-chemistry` / `patent-domain-mechanical` / `patent-domain-electrical` 管**领域术语与实施例习惯**；本 skill 管**修改流程与输出格式**。若用户已选某领域 Agent，读完本文件后再读对应 domain 的 `SKILL.md`。

## 输出前质量检查清单

改模式输出前逐项检查。检查分两部分：通用检查 + 按修改章节触发的对应检查项。

### 通用检查（每轮必检）

- [ ] 已明确修改范围并告知用户（直接修改 / 联动更新 / 不改动）
- [ ] 只输出了被修改的段落，未全文重写
- [ ] 每个修改段落标明了章节路径，用户可直接复制
- [ ] 未展示 diff 格式（红绿行、SEARCH/REPLACE 块等）
- [ ] 已检查联动更新项，并同步输出（或明确告知无需联动）
- [ ] 未编造实验数据或审查员原话
- [ ] 已读取 `workspace/patent-draft.md` 获取最新状态
- [ ] 修改后的段落已写回 `workspace/patent-draft.md`

### 按章节触发的质量检查

修改了哪个章节，就检查对应项。未修改的章节不检查。

- [ ] **摘要**：≤300字（含标点）；一段到底、无小标题；含名称/领域/问题/方案要点/用途
- [ ] **权利要求书**：连续编号，无跳号/重复号；独权至少2项且类型成对（方法+产品），第二独权用引用型写法；从属引用编号存在且 ≤ 当前编号；无点值罗列，范围用 `~` 分隔；独权含核心区别特征；独立项/从属项用语正确；方法从属与产品从属各自成链
- [ ] **背景技术**：至少 3 段；无虚构文献；缺陷与方案对应
- [ ] **发明内容-技术问题**：段落化书写，非碎片列表
- [ ] **发明内容-技术方案**：一条流，从属用「优选地」嵌入；无另立「从属技术方案」节；与权利要求逐项可对上
- [ ] **发明内容-核心技术点**：每个核心特征后写了原理/作用/效果
- [ ] **发明内容-有益效果**：按独立贡献点计数（4～8条）；每条写完整因果链（手段→机理→缺陷避免→结构改善→性能提升）；协同效果整体写不拆分；无具体实验数值（交底数值已改写为趋势性描述）；与方案/问题对应
- [ ] **具体实施方式-实施例/对比例**：标题独占一行，正文另起段；≥3 实施例 + ≥2 对比例（如为新增）；缺数据用 XX 占位，无编造；每个发明点有对应对比例；每个对比例只改变一个变量；实施例未照抄交底书，已重写为专利体例
- [ ] **具体实施方式-实施例前**：集中了原料信息和测试方法
- [ ] **具体实施方式-参数对照表**：实施例≥3 且对比例≥2 时已生成；数据与正文一致
- [ ] **具体实施方式-对比总结**：集中于一个节（可分多段落但不分散、不编号列表），逐一覆盖全部实施例和对比例，不漏项
- [ ] **Markdown 格式**：所有标题使用 `#` 语法
