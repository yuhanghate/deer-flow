# 专利撰写 — 化学领域

## 本 skill 解决什么

化学案最容易在**可重复性、范围与支持**上出缝隙：实施例不够具体、范围与数据脱节。本 skill 让模型优先把**可写进说明书的事实链**补全，并把风险标给代理人。

**可选 PDF 附件**：通用《审查指南》与跨领域样板见 `patent-cn-core/resources/`。若要从 PDF **抽取整篇正文或表格**（非仅肉眼看版式），按需加载技能 **`pdf`**（`skills/public/pdf/SKILL.md`），与 `patent-cn-core` 中说明一致。

**摘要**：整套专利文稿须含**说明书摘要**，**≤300 字（含标点）**、无标题行——见 `patent-cn-core` 的「Step 2：摘要」。

**超长上下文**：`config.yaml` 中 `summarization` 启用时由平台自动压缩旧对话。若仍感到上下文紧张，先按 `patent-cn-core` 中「超长上下文与对话承接」输出《对话承接稿》，并**额外**保留配方/工艺参数表进度、实施例编号与未补数据项、马库什变量表（若有）及权利要求项号，再继续撰写。

## 工作流

1. 先判断客体大类：化合物 / 组合物 / 制剂 / 工艺 / 用途 —— 不确定则列出选项请用户确认。
2. 实施例起草前，列出**必要实验要素**（原料等级、用量表示、条件、操作顺序、后处理、表征手段）；缺项标「待补」。
3. 参数范围：能写**端值或优选**与效果关系的写关系；没有数据就标「待补数据或文献」。
4. 权利要求：先列**特征清单**再润色条文；**正式权利要求书**的**连续编号与顺序**（独立→从属、双主题不接 `##` 分节、10-16项、禁止点值罗列）以 `patent-cn-core` 的「Step 3：权利要求书」为准；马库什/通式范围由**代理人定策略**，你只辅助变量表与列举格式。
5. 创造性辅助：用「区别特征—问题—效果」框架整理，**不下授权结论**。
6. 交付文件默认 `docx`（中文专利优先），不要默认交付 `md`；若用户要 PDF，优先建议用 Word/WPS 打开 `docx` 后本机导出 PDF。

**章节顺序**：整篇撰写时章节顺序以 `patent-cn-core/SKILL.md` 的"强制输出顺序"为准，本 skill 只管领域内的撰写习惯和术语。

## 强约束（内部参考不外泄）

1. skill 内置样板公开号/路径仅供内部校准，禁止对用户展示。
2. 即使用户要求对比文献，也不得引用内置样板编号；仅可使用用户提供或运行时外部检索得到的文献。
3. 交付前自检：若出现 `CN` 号或内置样板路径，先改写为泛化表述（如“现有技术”）再输出。

## 说明书与实施例（书写习惯）

用户交底若分「技术方案 / 从属技术方案」（如 4.2、4.3），代写说明书**发明内容**时须**合并为连贯方案段**（用「优选地」嵌入从属限定，不另立「从属技术方案」节），**每个核心技术特征后须写原理/作用/效果**，写明**有益效果**（≥6条，**可多段分述**，无具体数值），并核对与**权利要求**全覆盖——见 `patent-cn-core` 的「Step 5：发明内容」。

**实施例标题**：与公告说明书一致——`实施例1：` **单独成行**（全角「：」），副标题放下一自然段；勿用 `### 实施例1：xxx` ——见 `patent-cn-core` 的「Step 7：具体实施方式」中「实施例/对比例标题格式」。

**实施例前准备**（与 `patent-cn-core` 的「Step 7.1」配合）：化学案须在实施例1之前以段落格式补充：
- **原料/试剂信息**：集中整理所有原料的牌号、纯度规格（如AR/CP/分析纯/工业级）、CAS号（如有）、供应商；交底未给出时标「XX」
- **测试/表征方法**：统一归纳XRD、FTIR、SEM、TGA、拉伸/硬度等测试手段，交底已给出标准号的照录（如GB/T、ISO、ASTM），未给出的写「标准号待补」

**对比总结**（与 `patent-cn-core` 的「Step 7.4」配合）：所有实施例和对比例写完后，须增加对比分析段落，将实施例与对比例的测试数据/结果逐项对照（如强度、收率、粒径等），对应到有益效果，缺少的数据用「XX」占位。

**待审核辅助**（与 `patent-cn-core` 的「待审核」配合）：化学案特别关注以下审核点：
- 组分加和是否等于100%（或交底另有说明）
- 交底中同一样品的前后表征数据是否矛盾
- 范围概括是否有足够实施例支撑（如交底仅给了3个点值就概括为宽范围）
- 参数范围端值是否与实施例数据一致
- **点值转范围**：交底中的温度、压力、配比、浓度、pH、时间等参数若给出多组离散点值，检查是否已在权利要求中概括为范围值（取最小值~最大值）；若点值间隔过大或存在离散聚集区，提醒代理人考虑拆分范围或并列写法；端值修饰（"约""大约"）由代理师决定

写实施例时，保证本领域技术人员能**重复**关键实验：原料、用量（与权利要求中计量方式一致）、条件、步骤顺序、后处理。避免只有效果没有实现路径。

表格与列表中：百分含量、摩尔比、固含量等**单位统一**，各组分加和与工艺逻辑合理（代理人核对实际配方规则）。

## 化学式与符号（为何 MD 粘到 WPS 会「断开」）

**模型输出约定**：无机式、简写材料名等写成**紧凑文本**，如 `Al₂O₃`、`Li₂O`、`ZrO₂`；**元素符号与下标之间、各化学式之间**均**不加空格**；中文列举用顿号 **`、` 紧贴**前后字符，勿写成 ` 、 `。

**常见原因（第一部分错、第二部分对）**：

1. **从 Markdown「预览」或网页里复制**：剪贴板常带 **HTML**（下标、加粗被拆成多个标签），边界处会被粘贴成**普通空格**，于是出现 `Al₂ O₃`、`Li₂ O` 这种断开。手打是在 WPS 里直接输入，没有这层转换，故正常。  
2. **MD 源文件里本来就写了空格**（换行对齐、从 PDF 再拷贝残留等），复制正文时一并带上。  
3. **混用半角空格与全角标点**：在 `、` 两侧多打了空格，粘贴后仍保留。

**给用户的最小操作建议**：优先从 **.md 源码纯文本**（编辑器里的原始一行）复制；若必须从预览复制，到 WPS 后用查找替换去掉「下标与字母之间的多余空格」和「顿号两侧空格」。需要上标/下标格式时，再在 WPS 里对个别字符设字体效果，勿依赖带空格的「假下标」文本。

## 权利要求（化学常见形态）

组合物：写清**组分 + 含量表示方式**（如质量%、摩尔分数等），与实施例一致。

工艺：步骤顺序与**关键条件**绑定；避免宽到无实施例支撑。

马库什/通式：**代理师把握保护范围**；你可输出「取代基定义表 + 列举项草稿」供其删减。

## 审查相关提醒（非法律结论）

充分公开：是否需**过度实验**才能实现权利要求范围。创造性：你是否能列出**有据的区别特征**与**技术效果**；结论由代理师判断。

## 简短示例（实施例开头句式）

**示例（风格而非唯一格式）：**

在反应瓶中加入 A mol 化合物（1）、B mol 化合物（2）……在 C ℃ 下搅拌 D h，……后处理得到……

**避免：**「按常规方法反应得到目标产物」而无条件与用量。

## 不要做的事

编造实验数据、虚构对比文件、伪造审查意见或实验图谱说明。
泄露 skill 内置样板的公开号、文件路径或引用片段。
