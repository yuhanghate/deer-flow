# 专利工作流入口（交底书 Intake）

## 作用定位

本 skill 只做入口把关，不替代领域写作。目标是把“收到交底书就直接写全文”的流程，改成“先补全、后起草、再质检”的稳定流程。

## 启动条件

满足任一条件即触发：

1. 用户上传了技术交底书（或交底摘要、研发报告、实验记录）。
2. 用户要求“生成专利申请文件/权利要求书/说明书”。
3. 用户提到“提高专利生成质量”“按中国专利法规范撰写”。

## 执行顺序（必须按序）

1. **材料审查**：识别输入材料类型（交底书、现有权利要求、审查意见、补充实验数据），并列出缺失材料。
2. **信息补全**：输出《关键信息缺失清单》（建议 <=12 项），格式固定为「缺失信息-影响-建议补充内容」。
3. **暂定假设**：信息不足时输出《暂定假设表》，后续正文中统一前缀「待代理人核实：」。
4. **任务分流**：
   - 通用结构与合规逻辑 -> `patent-cn-core`
   - 机械结构案 -> `patent-domain-mechanical`
   - 化学材料案 -> `patent-domain-chemistry`
   - 电学软硬件案 -> `patent-domain-electrical`
5. **起草策略**：先给“创新点提炼 + 权利要求框架”，确认后再给说明书各部分草稿。
6. **质量门禁**：未通过门禁不得交付最终稿。

## 强制质量门禁（未满足则继续迭代）

1. **权利要求门禁**：权利要求 **10～16 项**（常规可先框 10 项再按交底扩展）；默认 **1 项独立**；仅当交底显示存在 **可并列保护且可分别支持** 的完整方案时，再规划 **第二项不同类型** 的独立权利要求，**禁止**为凑类型硬造空壳独权。语言简练，避免非必要特征与空泛术语；自定义术语在框架中注明「须在说明书定义/指称」。
2. **背景技术门禁**：必须覆盖现有技术、最接近方案、现有缺陷及本方案的对应改进关系；无文献依据处不得捏造具体对比文件或产品型号。
3. **技术点效果门禁**：每个技术点至少给出原理/作用/效果之一，并可追溯到方案特征。
4. **有益效果门禁**：至少 **6 条**；交底不足以归纳 6 条时，列出现有条目并注明缺口，**不得**为凑数编造效果。
5. **实施例门禁**：至少 3 个实施例 + 2 个对比例，须能服务于权项技术点的对比论证。测试条件、关键参数、结果数据 **有则列、无则占位（XX/待补）**；**禁止编造**数值与标准编号；对比结论仅基于已提供或可占位之处归纳，不虚构实验结果。
6. **范围概括门禁**：关键成分或步骤先做上位概括，再给优选范围与可选方案。
7. **交付分层门禁**：入口阶段即提醒下游：`patent-cn-core` 要求 **递交用正文** 与 **「进一步改进建议」「待审核」等工作附件** 分离，后者不得写入拟递交的说明书六部分体例内。
8. **风险备注门禁**：输出《待申请人确认事项》，标注不清楚或需完善处。
9. **合规自检门禁**：输出《合规自检清单》，覆盖清楚性、支持性、单一性、可实施性、术语一致性。

## 输出模板（入口阶段）

```markdown
## 输入材料识别
- 已提供：
- 缺失：

## 关键信息缺失清单
1) 缺失信息 - 影响 - 建议补充内容

## 暂定假设表（如适用）
1) 假设内容 - 使用位置 - 风险说明

## 创新点提炼（必要/可选）
1) ...

## 权利要求框架（10～16 项，先列骨架再扩写）
1) 独立权利要求（草案方向；是否需第二独权及类型并列理由）
2) 从属权利要求（逐项列展开方向与引用挂点，总项数含独权落在 10～16）

## 分流建议
- 结构合规：patent-cn-core
- 领域技能：mechanical / chemistry / electrical

## 待申请人确认事项
1) ...
```

## 超长上下文与对话承接

1. **平台层**：DeerFlow 在 `config.yaml` 的 `summarization` 会对整条对话自动压缩较早消息（与具体 skill 无关）。需要摘要更贴合专利语义时，可在同文件配置全局 `summary_prompt`。
2. **本 skill**：在继续分流或质检前，若你感知上下文将满、或对话历史已被中间层摘要，先输出不超过约 400 字的 **《对话承接稿》**，须包含：材料类型与已提供项、缺失清单题号、暂定假设编号、创新点与权利要求框架（含项号约定）、拟启用的下游技能（`patent-cn-core` 与哪类 domain）、待申请人确认事项汇总。后续轮次以该承接稿为工作真源，避免依赖可能已被摘要掉的细枝末节。
3. **不要**把内部样板路径、公告号或密级字段写入承接稿。

## 不要做的事

1. 未完成信息补全就直接输出“可递交终稿”。
2. 编造实验数据、对比文件、审查员意见或法律结论。
3. 泄露任何内部样板路径、公开号或参考附件编号。
