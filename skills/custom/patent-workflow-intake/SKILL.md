# 专利工作流入口（交底书 Intake）

## 作用定位

本 skill 只做入口把关，不替代领域写作。目标是把“收到交底书就直接写全文”的流程，改成“先补全、后起草、再质检”的稳定流程。

## 启动条件

满足任一条件即触发：

1. 用户上传了技术交底书（或交底摘要、研发报告、实验记录）。
2. 用户要求“生成专利申请文件/权利要求书/说明书”。
3. 用户提到“提高专利生成质量”“按中国专利法规范撰写”。

## 执行顺序（必须按序）

1. **材料审查**：识别输入材料类型（交底书、现有权利要求、审查意见、补充实验数据），并列出缺失材料。
2. **信息补全**：输出《关键信息缺失清单》（建议 <=12 项），格式固定为「缺失信息-影响-建议补充内容」。
3. **暂定假设**：信息不足时输出《暂定假设表》，后续正文中统一前缀「待代理人核实：」。
4. **任务分流**：
   - 通用结构与合规逻辑 -> `patent-cn-core`
   - 机械结构案 -> `patent-domain-mechanical`
   - 化学材料案 -> `patent-domain-chemistry`
   - 电学软硬件案 -> `patent-domain-electrical`
5. **起草策略**：先给“创新点提炼 + 权利要求框架”，确认后再给说明书各部分草稿。
6. **质量门禁**：未通过门禁不得交付最终稿。

## 强制质量门禁（未满足则继续迭代）

1. **权利要求门禁**：默认 10 项；语言简练，避免非必要特征与空泛术语。
2. **背景技术门禁**：必须覆盖现有技术、最接近方案、现有缺陷及本方案的对应改进关系。
3. **技术点效果门禁**：每个技术点至少给出原理/作用/效果之一，并可追溯到方案特征。
4. **有益效果门禁**：至少 5 条，且逐条对应技术方案，不写宣传性结论。
5. **实施例门禁**：至少 3 个实施例 + 2 个对比例，含测试条件、关键参数、结果数据与对比结论。
6. **范围概括门禁**：关键成分或步骤先做上位概括，再给优选范围与可选方案。
7. **风险备注门禁**：输出《待申请人确认事项》，标注不清楚或需完善处。
8. **合规自检门禁**：输出《合规自检清单》，覆盖清楚性、支持性、单一性、可实施性、术语一致性。

## 输出模板（入口阶段）

```markdown
## 输入材料识别
- 已提供：
- 缺失：

## 关键信息缺失清单
1) 缺失信息 - 影响 - 建议补充内容

## 暂定假设表（如适用）
1) 假设内容 - 使用位置 - 风险说明

## 创新点提炼（必要/可选）
1) ...

## 权利要求框架（10项）
1) 独立权利要求（草案方向）
2)-10) 从属权利要求（展开方向）

## 分流建议
- 结构合规：patent-cn-core
- 领域技能：mechanical / chemistry / electrical

## 待申请人确认事项
1) ...
```

## 不要做的事

1. 未完成信息补全就直接输出“可递交终稿”。
2. 编造实验数据、对比文件、审查员意见或法律结论。
3. 泄露任何内部样板路径、公开号或参考附件编号。
