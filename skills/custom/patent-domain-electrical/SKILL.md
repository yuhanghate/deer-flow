# 专利撰写 — 电学领域

## 本 skill 解决什么

电学案常见痛点是**模块边界不清、软硬件混写导致支持不足、方法步骤与装置不对齐**。本 skill 让模型先理顺**信号/数据与控制流**，再落到权利要求类型选择上（由代理师定装置/方法/介质等策略）。

**可选 PDF 附件**：通用资料见 `patent-cn-core/resources/`。若要从 PDF **抽取整篇正文或表格**，按需加载技能 **`pdf`**（`skills/public/pdf/SKILL.md`），与 `patent-cn-core` 中说明一致。

**摘要**：见 `patent-cn-core` 的「Step 2：摘要」；样板见 `patent-cn-core/resources/samples/electrical/`。

**超长上下文**：`config.yaml` 中 `summarization` 启用时由平台自动压缩旧对话。若仍感到上下文紧张，先按 `patent-cn-core` 中「超长上下文与对话承接」输出《对话承接稿》，并**额外**保留模块—接口—数据流约定、方法步骤与装置权项的对应关系及当前项号，再继续撰写。

## 工作流

1. 先画清**逻辑结构**：输入源 → 处理单元 → 输出/执行；标出反馈环与异常路径（若交底中有）。
2. 说明书实施方式：先总述**系统组成**，再分模块写**输入、输出、处理步骤、与其他模块的接口**。
3. 若涉及程序：写清**与硬件的结合点**（由哪个处理器执行、读哪路信号、写哪个寄存器/总线），避免「纯软件流程」飘在空中。
4. 时序相关：写清时钟、采样率、超时、阈值等；无实施例支撑的范围标「待补」。
5. 权利要求：装置项写清**模块 + 连接关系**；方法项写清**步骤顺序与依赖**；两套用语**对齐**；**正式权利要求书**版式与编号流（独立→从属、双主题不接 `##` 分节、10-16项、禁止点值罗列）见 `patent-cn-core` 的「Step 3：权利要求书」。
6. 交付文件默认 `docx`（中文专利优先），不要默认交付 `md`；若用户要 PDF，优先建议用 Word/WPS 打开 `docx` 后本机导出 PDF。

**章节顺序**：整篇撰写时章节顺序以 `patent-cn-core/SKILL.md` 的"强制输出顺序"为准，本 skill 只管领域内的撰写习惯和术语。

## 强约束（内部参考不外泄）

1. skill 内置样板公开号/路径仅供内部校准，禁止对用户展示。
2. 即使用户要求对比文献，也不得引用内置样板编号；仅可使用用户提供或运行时外部检索得到的文献。
3. 交付前自检：若出现 `CN` 号或内置样板路径，先改写为泛化表述（如“现有技术”）再输出。

## 发明内容（与 core 一致）

说明书第三节须含**技术问题、技术方案（含优选层次，不另立从属技术方案节）、有益效果**（≥6条，**可多段分述**，无具体数值）；**每个核心技术特征后须写原理/作用/效果**——见 `patent-cn-core` 的「Step 5：发明内容」。

**实施例标题**：`实施例1：` **单独成行**（全角「：」），勿用 `### 实施例1：副标题` ——见 `patent-cn-core` 的「Step 7：具体实施方式」中「实施例/对比例标题格式」。

## 说明书习惯

用「模块图 + 文字」说明**数据流与控制流**；对关键算法可用步骤描述，但保留与**具体硬件或执行环境**的锚点（代理师决定撰写深度）。

提醒代理人注意：**纯商业规则、非技术特征**堆砌可能被质疑客体；你只作提醒，不替代判断。

## 具体实施方式（与 core 配合）

**实施例前准备**（与 `patent-cn-core` 的「Step 7.1」配合）：电学案须在实施例1之前以段落格式补充：
- **器件/模块信息**：集中整理涉及的芯片型号、传感器规格、通信协议版本、接口标准等
- **测试/验证方法**：统一归纳功能测试、信号采集、通信测试等方法，交底已给出标准号的照录（如IEEE、IEC、3GPP），未给出的写「标准号待补」

**对比总结**（与 `patent-cn-core` 的「Step 7.4」配合）：所有实施例和对比例写完后，须增加对比分析段落，将实施例与对比例的测试数据/结果逐项对照（如响应时间、精度、功耗等），对应到有益效果。

**待审核辅助**（与 `patent-cn-core` 的「待审核」配合）：电学案特别关注：
- 方法步骤与装置模块的对应关系是否清楚
- 时序参数（采样率、超时、阈值）前后是否一致
- 算法步骤是否有硬件执行锚点（非纯软件流程）
- 功能性限定在说明书中是否有具体电路/程序实现
- **点值转范围**：交底中若给出多组离散参数（如电压阈值、频率、电阻值等），检查是否已概括为范围值；若点值间隔过大（如 1V、50V、200V）提醒代理人注意范围概括的支持性

## 权利要求（电学常见搭配）

装置：功能模块应能对应到**结构或电路实体**上的划分（在代理师接受的抽象层级内）。

方法：步骤之间**依赖关系**明确（哪些步骤必须在前）。

若用户要「装置 + 方法」双套，先列**共用术语表**再分别起草，避免同一概念两名。

## 简短示例（模块描述句式）

**示例：**

处理单元（102）被配置为：接收来自传感器接口（101）的采样序列；当所述采样序列满足预定条件时，向驱动电路（103）输出控制信号……

**避免：**「智能地处理数据」而无输入输出与条件。

## 不要做的事

编造波形、时序参数、标准号、芯片型号与引脚定义；虚构通信协议细节。
泄露 skill 内置样板的公开号、文件路径或引用片段。
