# 专利撰写 — 电学领域

## 本 skill 解决什么

电学案常见痛点是**模块边界不清、软硬件混写导致支持不足、方法步骤与装置不对齐**。本 skill 让模型先理顺**信号/数据与控制流**，再落到权利要求类型选择上（由代理师定装置/方法/介质等策略）。

**可选 PDF 附件**：通用资料见 `patent-cn-core/resources/`；电学专用见本 skill **`resources/`**（`resources/README.md`）。若要从 PDF **抽取整篇正文或表格**，按需加载技能 **`pdf`**（`skills/public/pdf/SKILL.md`），与 `patent-cn-core` 中说明一致。

**摘要**：见 `patent-cn-core/references/abstract-summary.md`；样板见 `patent-cn-core/resources/samples/electrical/`（均为**可抽取文字层**公告 PDF，便于全文对照）。

## 工作流

1. 先画清**逻辑结构**：输入源 → 处理单元 → 输出/执行；标出反馈环与异常路径（若交底中有）。
2. 说明书实施方式：先总述**系统组成**，再分模块写**输入、输出、处理步骤、与其他模块的接口**。
3. 若涉及程序：写清**与硬件的结合点**（由哪个处理器执行、读哪路信号、写哪个寄存器/总线），避免「纯软件流程」飘在空中。
4. 时序相关：写清时钟、采样率、超时、阈值等；无实施例支撑的范围标「待补」。
5. 权利要求：装置项写清**模块 + 连接关系**；方法项写清**步骤顺序与依赖**；两套用语**对齐**；**正式权利要求书**版式与编号流同上，见 `patent-cn-core/references/claims-layout-and-numbering.md`。
6. 交付文件默认 `docx`（中文专利优先），不要默认交付 `md`；若用户要 PDF，优先建议用 Word/WPS 打开 `docx` 后本机导出 PDF。

## 强约束（内部参考不外泄）

1. skill 内置样板公开号/路径仅供内部校准，禁止对用户展示。
2. 即使用户要求对比文献，也不得引用内置样板编号；仅可使用用户提供或运行时外部检索得到的文献。
3. 交付前自检：若出现 `CN` 号或内置样板路径，先改写为泛化表述（如“现有技术”）再输出。

## 发明内容（与 core 一致）

说明书第三节须含**技术问题、技术方案（含优选层次）、有益效果**；效果**可多段分述**——见 `patent-cn-core/references/specification-and-claims.md`。

**实施例标题**：`实施例1：` **单独成行**（全角「：」），勿用 `### 实施例1：副标题` ——同上文件「具体实施方式」节。

## 说明书习惯

用「模块图 + 文字」说明**数据流与控制流**；对关键算法可用步骤描述，但保留与**具体硬件或执行环境**的锚点（代理师决定撰写深度）。

提醒代理人注意：**纯商业规则、非技术特征**堆砌可能被质疑客体；你只作提醒，不替代判断。

## 权利要求（电学常见搭配）

装置：功能模块应能对应到**结构或电路实体**上的划分（在代理师接受的抽象层级内）。

方法：步骤之间**依赖关系**明确（哪些步骤必须在前）。

若用户要「装置 + 方法」双套，先列**共用术语表**再分别起草，避免同一概念两名。

## 简短示例（模块描述句式）

**示例：**

处理单元（102）被配置为：接收来自传感器接口（101）的采样序列；当所述采样序列满足预定条件时，向驱动电路（103）输出控制信号……

**避免：**「智能地处理数据」而无输入输出与条件。

## 不要做的事

编造波形、时序参数、标准号、芯片型号与引脚定义；虚构通信协议细节。
泄露 skill 内置样板的公开号、文件路径或引用片段。
